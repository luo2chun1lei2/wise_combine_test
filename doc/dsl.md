# DSL 语法定义（草案 v0.1）

本文件描述函数调用序列模型的 DSL。它用于表达函数之间的语义关系：资源生命周期、前置条件、状态变化，以及跨函数的资源依赖。

## 1. 设计目标

- 语法简单、可读，像模型描述文件而不是编程语言。
- 不自动推导语义，使用者显式声明资源状态和函数效果。
- 数据依赖通过返回值和参数类型自然表达，不额外写“谁给谁”。

## 2. 语法结构

### 2.1 注释

以 `#` 开始的行是注释。

### 2.2 资源类型

```
resource <名称> {
  states: <状态1>, <状态2>, ...
  initial: <初始状态>
}
```

资源是有生命周期、可以跨函数传递的对象，例如文件句柄。

### 2.3 函数

```
func <函数名>(<参数>, ...) [-> <返回类型>] {
  requires: [<条件>, ...]
  effects: [<效果>, ...]
}
```

- 参数写成 `名称: 类型`。
- 返回类型用 `->` 表示，可以省略表示无返回值。
- `requires` 是调用前必须满足的条件，为空表示无条件。
- `effects` 是调用后资源状态的变化，为空表示所有资源状态不变。

### 2.4 类型

- 内建类型：`string`、`int`、`bool`。
- 资源类型：由 `resource` 声明的名称。

### 2.5 条件与效果

- 条件形式：`<参数名> is <状态>`，多个条件用逗号分隔。
- 效果形式：`<目标> -> <状态>`，多个效果用逗号分隔。
- `result` 是关键字，特指函数返回值。

## 3. 语义

### 3.1 生产者与消费者

- 返回资源类型的函数是**生产者**，每调用一次就产生一个新的资源实例。
- 参数为资源类型的函数是**消费者**，参数必须绑定到一个已存在的资源实例。

### 3.2 资源实例环境

生成器维护一个实例环境，记录每个已产生实例及其当前状态。调用函数时，每个资源参数都要从环境里选一个当前状态满足 `requires` 的实例来绑定。

### 3.3 合法调用序列

从空环境开始，每一步都满足 `requires` 且资源绑定有效的调用序列，称为合法调用序列。

## 4. 最小样例：文件句柄

```
# 文件句柄有两种状态，初始为关闭
resource FileHandle {
  states: CLOSED, OPEN
  initial: CLOSED
}

# 打开文件：产生一个新句柄，并使其处于 OPEN
func open(path: string) -> FileHandle {
  requires:
  effects: result -> OPEN
}

# 写入数据：需要一个已打开的句柄，写完后句柄仍为 OPEN
func write(h: FileHandle, data: string) -> int {
  requires: h is OPEN
  effects: h -> OPEN
}

# 关闭句柄：需要一个已打开的句柄，关闭后处于 CLOSED
func close(h: FileHandle) -> int {
  requires: h is OPEN
  effects: h -> CLOSED
}
```

## 5. 已确定的决策（第一版）

1. **值参数**：非资源参数（如 `path`、`data`）在第一版中作为符号占位，不赋予具体取值。
2. **返回与错误语义**：第一版假设返回资源即成功，不处理失败或错误返回。
3. **多实例**：允许同一序列中出现多个同类型资源实例；每个资源参数绑定到一个满足条件的已存在实例。

## 6. 尚未解决或后续扩展

- 资源参数是否允许两个参数绑定到同一实例（别名问题）。
- 是否内置生成负向序列，即最后一步故意违反 `requires`。
- 条件表达式是否需要支持数值比较等更复杂形式。
- 生成时的长度上限和活跃实例数量上限。
