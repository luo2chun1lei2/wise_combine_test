# 组合测试工具（wise_combine_test）项目提案

## 1. 项目概述

本项目开发一个运行在 Linux 上的命令行组合测试工具，用于在用户描述接口之间的关系后，自动生成并执行各种组合调用流程，从而发现程序在对象状态迁移和函数组合调用过程中存在的问题。

核心能力包括：

- 通过描述对象的**状态图**，围绕对象的状态迁移函数进行测试。
- 通过描述一组**函数及其关系**（参数传递关系、调用顺序关系等），生成组合调用流程并执行，检测程序问题。

## 2. 背景与问题

在复杂系统中，接口并不是孤立工作的。函数之间存在调用顺序约束、参数之间的数据传递，以及对象内部状态的迁移依赖。仅对单个函数或单个状态做测试，无法覆盖这些组合场景。

组合调用流程的数量往往随函数数量和关系数量快速增长，人工枚举既不现实也容易遗漏。因此需要一种可描述的、自动化的组合测试方法：由用户声明状态图与函数关系，由工具负责枚举、执行和报告。

## 3. 需求

下面描述中，“[必须]”是必须实现，“[可选]”是可以选择实现。如果某个语句没有描述必须还是可选，那么看它上一级；如果直到最开始都没有说明，那么就是“必须”。

### 3.1 需求

组合测试：描述了接口的关系后，可以进行组合测试。

1. [必须] 可以通过描述对象的状态图，围绕着对象的状态迁移用的函数进行测试。
1. [必须] 可以通过描述一组函数和它们之间的关系，比如参数之间传递的关系，调用顺序的关系等，生成各种组合调用流程测试程序是否存在问题。

#### 问题判定标准

一次组合调用流程会被判定为**通过**或**失败**。判定为“发现程序问题”的信号包括：

- 被测程序崩溃或异常终止；
- 断言失败；
- 内存错误（内存泄露、内存越界访问、重复释放等，由 ASan / Valgrind 检测）；
- 实际输出或返回结果与用户提供的预期输出或预期结果不一致。

若用户未提供预期输出或预期结果，则以“不崩溃、无内存错误、无断言失败”作为最低通过标准。

#### 最小可运行示例

用户提供一个 DSL 描述，例如：

- 声明两个函数 `push(int x)` 与 `pop()`，并声明调用顺序关系：`pop` 只能在至少一次 `push` 之后调用；
- 声明预期输出或返回结果，或者只声明最低通过标准（不崩溃、无内存错误、无断言失败）。

工具据此生成并执行组合调用流程（例如先 `push` 再 `pop`、只调用 `push`、未 `push` 就 `pop` 等），并把每个流程的“通过/失败”结论写入报告。若某流程触发崩溃、断言失败、内存错误或与预期输出不符，则判定为发现程序问题。

## 5. 技术方案概述

### 5.1 平台与语言

- 目标平台：Linux。
- 实现语言：C++17，仅依赖 C++ 标准库与系统自带 POSIX 接口，不引入第三方库。

选择理由：

- C++ 标准库足以表达状态图、函数关系图和组合生成算法，无需第三方依赖。
- RAII 机制有助于降低工具自身的内存管理风险。
- 工具和生成的测试可方便地使用 ASan（AddressSanitizer）与 Valgrind 检查内存泄露和越界访问。

### 5.2 架构概览

工具按流水线组织为五个部分：

1. **描述前端**：解析用户编写的状态图与函数关系描述。
2. **内部模型**：将描述转换为可遍历的状态机模型与关系图模型。
3. **组合生成器**：根据模型生成组合调用流程，并支持边界与剪枝以控制规模。
4. **执行器**：加载用户提供的被测函数并驱动调用。
5. **报告与日志**：输出执行结果，记录运行过程并辅助定位错误，支持日志大小上限、轮转或清理。

### 5.3 执行与内存检查

执行器支持两种模式：

- **直接执行模式**：进程内通过 `dlopen` 加载用户共享库并直接驱动调用，适用于常规组合测试。
- **独立被测程序模式**：生成可独立编译、链接的被测主程序，便于在 ASan 或 Valgrind 下运行，完成内存泄露和内存越界检查。

## 9. 风险与对策

- **组合爆炸**：组合调用流程数量可能急剧增长。对策是在模型中提供深度、路径数量等可配置上限，并结合剪枝策略。
- **状态空间不可穷尽**：对策是采用有界模型检查思路，允许用户设定迭代深度与终止条件。
- **动态生成代码的内存检查**：对策是提供独立被测程序生成能力，统一在 ASan / Valgrind 下检查。
- **无第三方依赖带来的开发成本**：对策是限定标准库范围，优先采用成熟、简单的数据结构和算法。

## 10. 关键决策

- 采用 C++17 + 标准库作为实现方案，以满足「不引入第三方库」和内存安全检查要求。
- 采用「直接执行 + 独立被测程序」双模式，兼顾使用便利性与内存检查的可靠性。
- 描述语言采用自定义文本格式，避免引入第三方解析库。
