# 设计文档

本文档描述工具的整体设计，汇总各架构决定，并说明各模块的职责与关系。架构决定详见 `ai/adr.md`。

## 1. 概述

本项目是一个基于模型的测试工具，用于两类测试：

- 函数调用序列测试：生成并执行有语义关系的函数调用序列。
- 状态机路径测试：按状态图生成并执行不同长度和途径的路径。

第一版直接做到完整执行并校验（ADR-020）。

## 2. 总体架构

工具分三个主要阶段，按顺序执行：

1. 解析模型：读取函数调用序列 DSL 或状态机 DSL，构建内部模型。
2. 生成用例：根据模型和覆盖准则生成调用序列或状态路径。
3. 执行与校验：运行生成的用例，按 oracle 判断结果，输出报告。

执行阶段通过“序列执行器 + 适配层”支持三种对接方式（ADR-006）：

- 直接链接调用。
- 编译成动态库加载。
- 生成桩代码交给外部框架。

三种方式共享序列执行核心，仅适配层不同。

## 3. 输入模型（DSL）

工具接受两类模型：

- 函数调用序列模型：见 `doc/dsl.md`，描述资源、函数、前置条件、状态效果、C 符号、C 类型、成功返回值和取值来源。
- 状态机模型：见 `doc/state-machine-dsl.md`，描述状态、事件、转换、guard、entry/exit 动作。

解析器使用 ANTLR 生成（ADR-021）。

## 4. 生成器

生成器负责从模型产生测试用例，遵循以下决定：

- 长度与终止：可配置最大长度，生成长度 1 到最大长度的合法序列或路径，有环时去环、去重以保证终止（ADR-015）。
- 覆盖准则：支持状态覆盖、转换覆盖、转换对覆盖、N-switch 覆盖和给定长度内的路径覆盖，作为命令选项（ADR-016）。
- 生成算法：支持 DFS/BFS、随机游走、中国邮路或转换游，作为测试时的选项（ADR-016）。
- 绑定与枚举：默认随机采样并固定种子，可选全枚举（ADR-017）。
- 参数别名：同一函数的不同资源参数禁止绑定同一实例（ADR-013）。
- 爆炸控制：去重、去环默认开启；指定覆盖准则时求最小覆盖集；抽样时用随机采样；另设最大用例数上限（ADR-018）。
- 负向序列：可选开关，默认关闭；生成方式为合法前缀加单个违规步骤（ADR-019）。

## 5. 执行层

执行层把生成的用例真正调用到被测函数或状态机上。

- 符号映射：DSL 中显式声明 C 函数符号和签名（ADR-010）。
- 类型映射：DSL 中显式声明资源类型和值类型对应的 C 类型（ADR-011）。
- 状态观测：优先要求被测接口提供状态观察函数；未提供时，退化为检查返回值是否正常和程序是否崩溃（ADR-008）。
- 值参数取值：外部提供值的范围或列表，执行时随机选择，并由随机种子保证可复现（ADR-009）。
- 返回值与错误：DSL 中声明成功返回值；执行时返回值不匹配即判定该序列失败并终止（ADR-012）。
- 正确性判定：基本判定为崩溃、超时或返回值异常；提供状态观察函数时，再用模型预期状态校验实际状态（ADR-024）。

## 6. 报告与复现

- 默认输出文本报告，并支持失败路径回放。
- 可选输出 JSON 报告，便于自动化（ADR-022）。
- 报告内容包括测试用例、失败信息和覆盖率。

## 7. 构建与解析

- 使用 C/C++ 实现，Makefile 负责编译、测试和安装。
- 解析器使用 ANTLR 从 `.g4` 语法生成，Makefile 包含代码生成步骤和运行时链接（ADR-021）。

## 8. 工具自身测试

- 以覆盖计数和合法性断言作为主力自动化回归测试。
- 由子智能体进行测试和评审。
- 关键算法可与参考实现对比（ADR-023）。

## 9. 目录结构

- `src/`：实现代码和编译构建脚本。
- `test/`：测试代码和编译构建脚本。
- `doc/`：面向客户的文档，包括 DSL 语法定义和示例。
- `ai/`：AI 与项目相关文件，包括提案、设计、任务和架构决定记录。

## 10. 演进计划

- 以实际例子驱动 DSL 扩展（ADR-007）。
- 示例函数组选择 libc 文件函数组和 `string.h` 字符串函数组（ADR-025）。
- 状态机第一版支持扁平 FSM、guard 和 entry/exit 动作，后续升级到嵌套、复合、历史和并发状态（ADR-014）。
