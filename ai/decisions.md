# 项目决策记录

本文档记录项目关键决策，并关联到 `ai/task.md` 中的任务编号。

## D1 实现语言与依赖

- 决策：使用 C++17，仅依赖 C++ 标准库与 POSIX 接口，不引入第三方库。
- 依据：满足 proposal 中「不引入第三方库」与内存检查要求。
- 关联任务：T1。

## D2 自定义文本 DSL

- 决策：使用自定义文本格式描述状态图与函数关系，避免第三方解析库。
- 依据：语法简单、可控，且符合无第三方依赖约束。
- 关联任务：T2、T3。

## D3 组合生成策略

- 决策：状态迁移使用有界 DFS，函数序列使用拓扑排序枚举，并结合互斥与组合约束过滤。
- 依据：兼顾完整性与组合爆炸控制。
- 关联任务：T4、T5、T14。

## D4 双执行模式

- 决策：执行器采用「直接执行模式 + 独立被测程序模式」。
- 依据：直接模式便于常规使用，独立程序便于在 ASan / Valgrind 下检查内存。
- 关联任务：T6、T7、T10。

## D5 固定调用约定

- 决策：被测函数统一使用 `extern "C" int <函数名>()` 的固定签名，返回 0 表示通过，非 0 表示失败。
- 依据：不依赖第三方类型信息即可直接加载并调用用户函数。
- 关联任务：T6、T7。

## D6 日志轮转策略

- 决策：日志默认写入 `build/wise_combine_test.log`，单文件达到默认 10 MiB 后轮转，保留最近 5 个文件。
- 依据：满足 proposal 中日志大小上限、轮转或清理的要求。
- 关联任务：T8。

## D7 参数数据流约束

- 决策：`parameter` 关系在模型层校验两端存在性与类型兼容，并在生成阶段要求生产者函数先于消费者函数出现；常量绑定与多级依赖参与数据流解析。
- 依据：让参数关系从“仅声明”变为真正影响组合生成与校验。
- 关联任务：T16、T17、T21。

## D8 守卫表达式

- 决策：状态迁移守卫使用 `return <比较符> <整数>` 的有限语法，在执行函数后按实际返回值求值，不满足守卫的流程记为失败。
- 依据：在不引入第三方表达式引擎的前提下，提供可验证的路径条件能力。
- 关联任务：T18。

## D9 生成策略接口化

- 决策：定义 `GenerationStrategy` 抽象接口，`Generator` 默认实现有界 DFS/拓扑排序，并允许通过 `set_strategy` 替换。
- 依据：为后续组合算法演进提供扩展点，同时保持现有行为不变。
- 关联任务：T22。

## D10 外部 adapter 执行协议

- 决策：新增 `--adapter` 执行模式，通过标准输入/输出的 JSON 协议调用外部 adapter；参数值沿 `parameter` 关系在步骤间传递。
- 依据：用进程隔离的 adapter 承载真实带参调用，避免 `dlopen` 对 C ABI 的依赖。
- 关联任务：T23、T24、T29。

## D11 逐函数预期输出

- 决策：adapter 响应中返回每个函数的标准输出，DSL 通过 `expect_output` 逐函数声明并比对预期输出。
- 依据：满足提案中“实际输出与预期输出不一致则失败”的判定标准。
- 关联任务：T28。
