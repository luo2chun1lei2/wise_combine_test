# 任务清单

本文档把 `ai/design.md` 的设计拆分为可执行的实现任务。任务按阶段排列，可随开发情况调整。

## 执行状态（截至 2026-09-10）

- 已完成：T1、T2、T3、T4、T5（主要能力）、T7（文本与 JSON）、T8、T9、T10（事件执行）、T11（文件示例端到端）、T13（自测脚本）、T14（README）。
- 已完成：T6（生成桩代码、直接链接、动态库加载、状态观察）、T12（输出缓冲区参数、值类型映射、无失败语义）。
- 已完成：T15（最终评审与文档一致性更新；代码提交待用户确认）。

## 后期任务状态（截至 2026-09-11）

- 已完成：T17（BFS）、T18（N-switch 覆盖）、T19（--bind 绑定策略）、T20（状态机事件执行 JSON 失败详情）、T21（success 逻辑组合）、T22（setup 预创建多实例）。
- 部分完成：T16（嵌套/复合状态已完成；历史状态、并发状态仍未实现）。

## 阶段 1：基础设施

- T1：建立 `src/`、`test/` 和 `Makefile` 骨架，采用 C/C++，使用 ANTLR 生成解析器（ADR-021）。
- T2：为函数调用序列 DSL 和状态机 DSL 编写 ANTLR 语法文件（`.g4`），覆盖 `doc/dsl.md` 和 `doc/state-machine-dsl.md` 的语法。
- T3：实现模型解析，把 DSL 文本转换为内部模型表示，并做语法和语义校验。

## 阶段 2：函数调用序列

- T4：解析并校验函数模型，包括资源、函数、`types`、`values`、符号、签名和成功返回值（ADR-002、ADR-010、ADR-011、ADR-012）。
- T5：实现序列生成器，支持长度上限、去环、去重、覆盖准则、生成算法、绑定枚举、爆炸控制和负向序列（ADR-013、ADR-015、ADR-016、ADR-017、ADR-018、ADR-019）。
- T6：实现执行层三种模式：直接链接、动态库加载、生成桩代码，以及状态观测、值参数随机取值、返回值检查（ADR-006、ADR-008、ADR-009、ADR-012）。
- T7：实现正确性判定和报告，包括文本报告、失败路径回放和可选 JSON 报告（ADR-022、ADR-024）。

## 阶段 3：状态机

- T8：解析并校验状态机模型，包括状态、事件、转换、guard 和 entry/exit 动作（ADR-014）。
- T9：实现状态机路径生成器，支持覆盖准则和生成算法（ADR-015、ADR-016、ADR-018）。
- T10：实现状态机路径执行与校验，按模型预期状态判定状态切换是否正确（ADR-024）。

## 阶段 4：示例与 DSL 扩展

- T11：使用 `doc/examples/` 下的 libc 文件函数组和字符串函数组作为示例，验证 DSL 和生成器（ADR-025）。
- T12：根据示例暴露的缺口扩展 DSL，至少包括：无资源函数、输出缓冲区参数、无失败语义、更多值类型映射、指针判空等 `success` 表达式、资源参数预创建多实例的语法。
- T13：建立工具自身测试，包括覆盖计数断言、合法性检查、子智能体评审和参考实现对比（ADR-023）。

## 阶段 5：文档与发布

- T14：编写中文 `README.md`，说明编译、测试、安装和使用方法，并链接到 `doc/` 下的详细文档。
- T15：更新 `doc/layout.md` 和 `ai/adr.md`，保证文档与实际结构一致，并完成最终评审和提交。

## 阶段 6：后期任务（Backlog）

以下任务来自 `ai/adr.md` 中标注“后续升级 / 尚未提供”的实现缺口。

- T16：状态机 DSL 升级到 ADR-014 方案 4，支持嵌套状态、复合状态、历史状态和并发状态。
- T17：为生成算法增加独立的 BFS 选项（ADR-016）。
- T18：增加转换对覆盖、N-switch 覆盖作为命令行选项，并使覆盖准则驱动生成（ADR-016）。
- T19：增加显式的“全枚举 / 随机采样”绑定策略命令开关（ADR-017）。
- T20：为 JSON 报告增加结构化失败详情，例如失败步骤、预期值、实际值（ADR-022）。
- T21：扩展 `success` 表达式，支持 `&&`、`||` 等逻辑组合。
