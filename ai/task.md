# 组合测试工具（wise_combine_test）任务计划

## 1. 说明

本文档将 `design.md` 中的设计拆解为可执行任务。任务按依赖顺序排列，每个任务包含目标、交付物与验收标准。优先级分为「必须」与「可选」。

每完成一个任务，均需按 AGENTS.md 要求将本目录文件（含 `.agents` 等）提交到 git 并推送到远程服务器。

## 2. 任务列表

### T1 项目骨架与构建系统（必须）

- 目标：建立可编译的 C++17 项目骨架，确定构建方式。
- 内容：创建 `src/`、`include/`、`tests/`、`examples/`、`docs/` 目录，配置不依赖第三方库的构建脚本。
- 交付物：可成功编译的最小可执行文件。
- 验收标准：干净环境执行构建成功，不引入第三方依赖。

### T2 描述语言解析器（必须）

- 目标：解析状态图与函数关系描述文件。
- 内容：实现词法/语法解析，支持 `object`、`state`、`transition`、`function`、`parameter`、`order` 等语法。
- 交付物：解析器模块及解析结果结构。
- 验收标准：能解析合法示例；对非法输入给出文件、行号与错误信息。

### T3 内部模型与语义校验（必须）

- 目标：将解析结果转换为状态机模型与函数关系模型，并执行语义校验。
- 内容：构建状态图邻接表、函数关系图、参数依赖图；校验状态/函数引用、类型兼容、`order` 无环、初始状态唯一等。
- 交付物：模型模块与校验逻辑。
- 验收标准：合法描述成功建模；各类非法描述被准确定位并拒绝。

### T4 状态迁移路径生成（必须）

- 目标：从初始状态生成到终止状态的迁移路径与调用序列。
- 内容：有界 DFS/BFS 遍历，支持最大步数、状态最大访问次数、重复路径剪枝。
- 交付物：状态迁移生成器。
- 验收标准：示例状态图生成预期路径，环路被正确截断。

### T5 函数调用序列生成（必须）

- 目标：根据函数关系生成满足调用顺序约束的组合调用序列。
- 内容：拓扑排序与无约束函数组合，结合参数数据流确定实参来源。
- 交付物：函数组合生成器。
- 验收标准：示例函数关系生成所有有效顺序，参数传递关系正确解析。

### T6 直接执行模式（必须）

- 目标：加载用户动态库并执行生成的调用流程。
- 内容：通过 `dlopen`/`dlsym` 解析函数符号，按调用序列执行，收集返回值与状态。
- 交付物：直接执行器。
- 验收标准：对示例动态库成功执行组合流程并报告结果。

### T7 独立被测程序生成（必须）

- 目标：生成可独立编译运行的被测主程序，支持内存检查。
- 内容：按调用流程生成 C/C++ 代码与调用逻辑，可被 ASan 编译或 Valgrind 运行。
- 交付物：独立被测程序生成器。
- 验收标准：生成代码可编译运行，并能在 ASan / Valgrind 下检查内存问题。

### T8 日志与报告（必须）

- 目标：记录运行过程与错误，输出结构化结果。
- 内容：实现多级别日志、失败流程现场信息、文本/JSON 报告、汇总统计。
- 交付物：日志与报告模块。
- 验收标准：成功与失败流程均可复现；报告格式正确。

### T9 单元测试（必须）

- 目标：覆盖 parser、model、generator、runner 各模块。
- 内容：为正常输入、非法输入与边界情况编写单元测试。
- 交付物：单元测试集。
- 验收标准：全部单元测试通过。

### T10 内存泄露与越界检查（必须）

- 目标：确认工具及被测程序无内存泄露与越界访问。
- 内容：工具以 ASan 构建并运行测试，独立被测程序在 ASan / Valgrind 下运行。
- 交付物：内存检查报告。
- 验收标准：检查无泄露与越界告警。

### T11 资源测量（必须）

- 目标：度量不同输入规模下的时间、内存与 CPU 占用。
- 内容：设计测量场景，记录调用流程数量与资源消耗关系。
- 交付物：测量报告。
- 验收标准：输出可复现的测量数据。

### T12 用户使用说明（必须）

- 目标：提供清晰、可执行的使用说明。
- 内容：描述 DSL、命令行参数、示例、构建与内存检查方法。
- 交付物：`docs/` 下使用说明文档。
- 验收标准：新用户可按文档完成一次组合测试。

### T13 代码覆盖率 80%（可选）

- 目标：使测试覆盖率达到 80%。
- 内容：使用覆盖率工具定位未覆盖分支并补充测试。
- 交付物：覆盖率报告。
- 验收标准：整体覆盖率不低于 80%。

### T14 接口关系可扩展性增强（可选）

- 目标：最大程度支持接口关系设定。
- 内容：扩展守卫表达式、多级参数传递、常量绑定、更丰富的调用顺序约束。
- 交付物：扩展后的 DSL 与模型支持。
- 验收标准：扩展语法可解析并参与生成，且不引入第三方依赖。

### T15 项目管理与决策记录（可选）

- 目标：记录项目管理步骤与重大决策，建立项目、代码、文档对应关系。
- 内容：维护决策记录文档，将提交与任务 ID 关联。
- 交付物：决策记录与对应关系说明。
- 验收标准：关键决策可追溯，提交与任务可对应。

## 3. 任务依赖

```
T1 -> T2 -> T3 -> T4 -> T6 -> T8
              -> T5 -> T6
                   -> T7
T2/T3/T4/T5/T6/T7/T8 -> T9 -> T10
                              -> T11
                              -> T13
T6/T7/T8 -> T12
T3/T5 -> T14
全程 -> T15
```

## 4. 执行顺序

1. 按依赖顺序先完成 T1 至 T8 的核心功能。
2. 完成 T9 单元测试。
3. 完成 T10 内存检查与 T11 资源测量。
4. 完成 T12 使用说明。
5. 视情况完成 T13、T14、T15 可选任务。

## 5. 提交规范

每个任务完成后执行：

1. 运行相关测试，确认通过。
2. 将本目录文件（含 `.agents` 等 AI 文件）加入 git。
3. 提交，提交信息包含任务 ID 与简要说明。
4. 推送到远程 `origin/plan_goal`。

编译和测试产生的二进制文件、构建目录按 `.gitignore` 排除，不提交。
