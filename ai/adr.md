# 架构决定记录（ADR）

本文件记录项目中的技术决定。每条记录包含状态、问题、可选方案、用户的选择、决定的简略影响以及决定时间。状态为“已接受”表示已定，“待选择”表示仍需讨论，后续决定后再更新对应记录。

## ADR-001：项目定位与测试方法

- 状态：已接受
- 决定时间：2026-09-09
- 问题：本项目要做哪种“组合测试”。
- 选择：
  1. 经典组合测试（t-way 参数取值组合、覆盖数组）。
  2. 函数调用序列测试（有语义关系的调用组合）。
  3. 状态机路径测试（按状态图遍历路径）。
- 用户选择：方案 2 和方案 3。
- 影响：工具聚焦语义调用序列和状态机路径生成，而非覆盖数组；DSL 面向资源生命周期和状态机。
- 详细说明：[doc/MBT.md](../doc/MBT.md)。

## ADR-002：函数调用序列的 DSL 语义表达

- 状态：已接受
- 决定时间：2026-09-09
- 问题：如何表达资源生命周期、前置条件、状态变化和跨函数数据依赖。
- 选择：
  1. 自定义文本 DSL，用 `resource`/`func`/`requires`/`effects`/`result` 表达。
  2. 使用 JSON 或 YAML 配置。
  3. 嵌入脚本语言。
- 用户选择：方案 1。
- 影响：DSL 可读性好、贴近模型描述；需要自行实现解析器；数据依赖通过类型推导，即返回资源表示生产、资源参数表示消费。

## ADR-003：值参数取值（第一版）

- 状态：已接受
- 决定时间：2026-09-09
- 问题：`path`、`data` 等非资源参数在生成序列时如何取值。
- 选择：
  1. 作为符号占位，不赋予具体取值。
  2. 为每个参数声明一个取值域。
  3. 使用固定默认值。
- 用户选择：方案 1。
- 影响：生成阶段只关心调用结构和资源依赖；真正执行时还需另定取值方式。

## ADR-004：返回与错误语义（第一版）

- 状态：已接受
- 决定时间：2026-09-09
- 问题：返回资源的函数是否考虑失败或错误返回。
- 选择：
  1. 返回资源即成功，不处理失败。
  2. 支持失败返回和错误分支。
- 用户选择：方案 1。
- 影响：DSL 更简单；执行层后续需要检查返回值。

## ADR-005：多实例

- 状态：已接受
- 决定时间：2026-09-09
- 问题：同一调用序列是否允许出现多个同类型资源实例。
- 选择：
  1. 允许，每个资源参数绑定到一个满足条件的已存在实例。
  2. 禁止，只允许单个实例。
- 用户选择：方案 1。
- 影响：生成器需要维护实例环境，复杂度上升，但更接近真实使用场景。

## ADR-006：执行层对接方式

- 状态：已接受
- 决定时间：2026-09-09
- 问题：工具如何真正调用被测函数。
- 选择：
  1. 直接链接调用。
  2. 编译成动态库加载。
  3. 生成桩代码交给外部框架。
  4. 纯生成、不执行。

- 影响：采用“序列执行器 + 适配层”架构，三种模式共享序列执行核心，由 harness 生成器统一产出驱动代码。

- 状态：已接受

- 选择：

  2. 一次性设计完整语法。
- 用户选择：方案 1。
- 影响：DSL 定义和实现逐步演进，先以最小样例落地，再按实际例子扩展。

## ADR-008：执行层状态观测方式

- 状态：已接受
- 决定时间：2026-09-10
- 问题：执行时如何得知资源实例的真实状态，以校验 `requires` 和 `effects`。
- 选择：
  1. 用户提供显式状态查询函数，例如 `is_open(h)`。
  2. 用返回值推断，例如 `fd >= 0` 视为 OPEN。
  3. harness 只维护模型状态，不观测真实状态。
  4. 组合：优先要求提供状态观察函数，没有则降级检查。
- 用户选择：方案 4，要求被测接口提供状态观察函数；未提供时，仅测试调用函数的返回值是否正常、程序是否崩溃。
- 影响：提供状态观察函数时可以校验状态切换；未提供时退化为检查返回值和崩溃，无法验证 `requires`/`effects` 中的状态约束，校验强度下降。与 ADR-024 相关。

## ADR-009：值参数在执行时的取值方式

- 状态：已接受
- 决定时间：2026-09-10
- 问题：真正运行序列时，`path`、`data` 等值参数如何获得具体值。
- 选择：
  1. 为每个参数声明一个取值域。
  2. 使用固定默认值。
  3. 由外部注入。
  4. 组合：外部提供值的范围或列表，执行时从中随机选择。
- 用户选择：方案 4。值来源由外部提供，例如参数的范围或列表；执行时从中随机选择一个作为测试值，不使用固定定值。资源类参数可先打开多个实例放入列表，再随机选择其中一个。
- 影响：需要定义取值来源（范围或列表）和随机选择机制；随机性要求引入随机种子以保证结果可复现。

## ADR-010：DSL 函数与真实符号的映射

- 状态：已接受
- 决定时间：2026-09-10
- 问题：DSL 中的函数如何映射到真实的 C/C++ 函数符号与签名。
- 选择：
  1. 使用命名约定自动映射。
  2. 在模型中显式声明符号和签名。
  3. 由构建配置提供映射。
- 用户选择：方案 2，在 DSL 中显式声明符号和签名。
- 影响：函数、状态等描述集中在一个模型里，便于统一检查和发现冲突或不完备；需要在 DSL 中增加符号与签名声明语法。

## ADR-011：资源类型与 C 类型映射

- 状态：已接受
- 决定时间：2026-09-10
- 问题：DSL 资源类型如何映射到运行时 C 类型，例如 `int fd`、`FILE*` 或自定义句柄。
- 选择：
  1. 在模型中显式声明 C 类型。
  2. 统一使用一种句柄类型，例如 `intptr_t`。
  3. 由适配层按执行模式处理。
- 用户选择：方案 1，在 DSL 中显式声明资源类型对应的 C 类型。
- 影响：需要在 DSL 中为资源类型和值类型声明 C 类型映射；模型集中描述，便于检查一致性。

## ADR-012：执行时的返回值与错误处理

- 状态：已接受
- 决定时间：2026-09-10
- 问题：真实执行时函数可能失败，例如 `open` 返回 -1，harness 如何检查并处理。
- 选择：
  1. 检查返回值，失败即终止该序列并记录。
  2. 失败后继续尝试后续合法步骤。
  3. 由用户提供判定规则。
- 用户选择：方案 1，并在 DSL 中为函数增加“成功返回值”声明；执行时返回值不匹配即判定该序列失败，默认终止该序列。
- 影响：需要扩展 DSL 支持成功返回值声明；失败序列不再继续执行，避免基于无效资源的后续调用。该声明已同步到 `doc/dsl.md`。

## ADR-013：参数别名

- 状态：已接受
- 决定时间：2026-09-10
- 问题：是否允许两个资源参数绑定到同一实例，例如 `write(h, h)`。
- 选择：
  1. 禁止。
  2. 允许。
  3. 作为可选配置。
- 用户选择：方案 1，禁止。
- 影响：生成器在绑定资源参数时需保证同一函数的不同资源参数绑定到不同实例，语义更简单，避免歧义。

## ADR-014：状态机 DSL 与语义边界

- 状态：已接受
- 决定时间：2026-09-10
- 问题：目标二的状态图 DSL 如何设计，支持到什么复杂度。
- 选择：
  1. 扁平 FSM，仅支持状态、事件和转换。
  2. 支持 guard 条件。
  3. 支持 entry/exit 动作。
  4. 支持嵌套、复合状态、历史状态或并发状态。
- 用户选择：方案 3，即扁平 FSM 加 guard 条件和 entry/exit 动作；后续需要升级到方案 4。
- 影响：第一版需要实现 guard 条件和 entry/exit 动作；嵌套、复合、历史、并发等高级特性留待后续版本升级。

## ADR-015：序列或路径长度与终止

- 状态：已接受
- 决定时间：2026-09-10
- 问题：“不同长度”如何定义，存在环时如何终止生成。
- 选择：
  1. 固定长度 1 到 N。
  2. 直到满足覆盖准则。
  3. 长度上限加去环。
- 用户选择：方案 3，并融合方案 1。使用可配置的 `max_length` 上限，生成长度从 1 到 `max_length` 的合法序列或路径；有环时通过路径内状态或实例去重、限制重复来避免无限膨胀并保证终止。
- 影响：生成器需要长度上限配置和去环、去重机制；长度可控且必定终止，后续覆盖准则可叠加在其上。
- 实现现状（2026-09-10）：当前函数序列生成通过 `--max-length` 上限和按调用文本去重来保证终止；状态机路径生成同样受长度上限约束，但允许同一状态/转换在路径中重复出现。

## ADR-016：覆盖准则与生成算法

- 状态：已接受
- 决定时间：2026-09-10
- 问题：生成时采用哪些覆盖准则以及相应算法。
- 选择：
  1. 状态覆盖。
  2. 转换覆盖。
  3. 转换对覆盖。
  4. N-switch 覆盖。
  5. 给定长度内的路径覆盖。
  6. 其他算法，如深度优先、广度优先、随机游走、中国邮路等。
- 用户选择：覆盖准则全部支持，作为命令选项；生成算法全部支持，即 DFS/BFS、随机游走、中国邮路或转换游，作为测试时的选项。
- 影响：工具需要实现多种覆盖准则和多种生成算法，并以命令行选项暴露；需要定义各准则与算法的组合方式、默认值和参数。
- 实现现状（2026-09-10）：函数模型默认 DFS 枚举，支持 `--algorithm random`；状态机默认 DFS 枚举，支持 `--algorithm random` 和 `--algorithm tour`。当前命令行尚未提供独立的 BFS、转换对覆盖、N-switch 覆盖选项，`--coverage` 仅做状态/转换或函数覆盖统计，`--cover` 做贪心最小覆盖。

## ADR-017：数据依赖绑定与枚举策略

- 状态：已接受
- 决定时间：2026-09-10
- 问题：存在多个候选实例时，生成器如何选择绑定并枚举序列。
- 选择：
  1. 全枚举所有合法绑定。
  2. 每个状态保留一个代表实例。
  3. 随机采样并固定种子。
- 用户选择：方案 3 作为默认，保留方案 1 作为可选；两者由命令选项控制。
- 影响：需要实现随机采样（带种子）和全枚举两种绑定策略；默认随机采样以控制规模，全枚举用于需要保证覆盖的场景。
- 实现现状（2026-09-10）：函数默认 DFS 中会对满足条件的资源实例做绑定枚举，但值参数取值和“文本去重”受固定随机种子影响；显式“全枚举/随机采样”命令开关尚未单独提供。

## ADR-018：组合爆炸控制

- 状态：已接受
- 决定时间：2026-09-10
- 问题：序列数量随长度和函数数量快速增长，如何控制规模。
- 选择：
  1. 去重或等价类。
  2. 求最小覆盖集。
  3. 随机采样并固定种子。
- 用户选择：三种手段组合使用，并做成策略或选项。去重、去环默认开启；指定覆盖准则时生成后求最小覆盖集；抽样时用随机采样加固定种子；另加最大用例数上限作为兜底。
- 影响：需要实现去重、去环、最小覆盖集、随机采样以及最大用例数限制，并按选项组合工作。

## ADR-019：负向序列

- 状态：已接受
- 决定时间：2026-09-10
- 问题：是否生成故意违反 `requires` 的负向序列。
- 选择：
  1. 不生成。
  2. 内置生成。
  3. 作为可选开关。
- 用户选择：方案 3，作为可选开关，默认关闭。
- 影响：需要实现负向序列生成，但默认不启用；开启后用例数会增加。

## ADR-022：报告与复现

- 状态：已接受
- 决定时间：2026-09-10
- 问题：测试用例、失败信息、覆盖率报告的格式，以及失败路径如何复现。
- 选择：
  1. 文本报告加路径回放。
  2. JSON 报告。
  3. 对接外部测试框架的报告。

## ADR-023：工具自身测试

- 状态：已接受
- 决定时间：2026-09-10

## ADR-024：正确性判定（oracle）

- 状态：已接受
- 决定时间：2026-09-10
- 问题：执行校验时，以什么作为“有问题”的判定依据。
- 选择：
  1. 以模型推导的预期状态或返回值作为 oracle。
  2. 由用户显式提供断言或预期结果。
  3. 只把崩溃、非零返回、超时视为失败。
  4. 以上方式的组合。
- 用户选择：方案 4。基本判定为崩溃、超时或返回值异常；若被测接口提供状态观察函数，则在关键步骤用模型推导的预期状态校验实际状态；未提供状态观察函数时，退化为仅检查返回值正常且不崩溃。
- 影响：校验强度取决于是否提供状态观察函数；无观察函数时只能发现崩溃和返回值异常，无法发现状态切换逻辑错误。“返回值正常”的具体判定规则由 ADR-012 中的 `success` 声明确定。

## ADR-025：示例函数组选择

- 状态：已接受
- 决定时间：2026-09-10
- 问题：用哪些真实函数组作为 DSL 的实践和扩展例子。
- 选择：
  1. libc 文件函数组，例如 `fopen`、`fwrite`、`fread`、`fclose` 等。
  2. libc 字符串处理函数组（`string.h`），例如 `strlen`、`strcpy`、`strcat`、`strcmp` 等。
  3. 其他函数组。
- 用户选择：方案 1 和方案 2。
- 影响：DSL 需要覆盖文件句柄和字符串缓冲区两类资源或生命周期场景，可据此验证并扩展 DSL。
