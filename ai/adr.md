# 架构决定记录（ADR）

本文件记录项目中的技术决定。每条记录包含状态、问题、可选方案、用户的选择、决定的简略影响以及决定时间。状态为“已接受”表示已定，“待选择”表示仍需讨论，后续决定后再更新对应记录。

## ADR-001：项目定位与测试方法

- 状态：已接受
- 决定时间：2026-09-09
- 问题：本项目要做哪种“组合测试”。
- 选择：
  1. 经典组合测试（t-way 参数取值组合、覆盖数组）。
  2. 函数调用序列测试（有语义关系的调用组合）。
  3. 状态机路径测试（按状态图遍历路径）。
- 用户选择：方案 2 和方案 3。
- 影响：工具聚焦语义调用序列和状态机路径生成，而非覆盖数组；DSL 面向资源生命周期和状态机。
- 详细说明：[doc/MBT.md](../doc/MBT.md)。

## ADR-002：函数调用序列的 DSL 语义表达

- 状态：已接受
- 决定时间：2026-09-09
- 问题：如何表达资源生命周期、前置条件、状态变化和跨函数数据依赖。
- 选择：
  1. 自定义文本 DSL，用 `resource`/`func`/`requires`/`effects`/`result` 表达。
  2. 使用 JSON 或 YAML 配置。
  3. 嵌入脚本语言。
- 用户选择：方案 1。
- 影响：DSL 可读性好、贴近模型描述；需要自行实现解析器；数据依赖通过类型推导，即返回资源表示生产、资源参数表示消费。

## ADR-003：值参数取值（第一版）

- 状态：已接受
- 决定时间：2026-09-09
- 问题：`path`、`data` 等非资源参数在生成序列时如何取值。
- 选择：
  1. 作为符号占位，不赋予具体取值。
  2. 为每个参数声明一个取值域。
  3. 使用固定默认值。
- 用户选择：方案 1。
- 影响：生成阶段只关心调用结构和资源依赖；真正执行时还需另定取值方式。

## ADR-004：返回与错误语义（第一版）

- 状态：已接受
- 决定时间：2026-09-09
- 问题：返回资源的函数是否考虑失败或错误返回。
- 选择：
  1. 返回资源即成功，不处理失败。
  2. 支持失败返回和错误分支。
- 用户选择：方案 1。
- 影响：DSL 更简单；执行层后续需要检查返回值。

## ADR-005：多实例

- 状态：已接受
- 决定时间：2026-09-09
- 问题：同一调用序列是否允许出现多个同类型资源实例。
- 选择：
  1. 允许，每个资源参数绑定到一个满足条件的已存在实例。
  2. 禁止，只允许单个实例。
- 用户选择：方案 1。
- 影响：生成器需要维护实例环境，复杂度上升，但更接近真实使用场景。

## ADR-006：执行层对接方式

- 状态：已接受
- 决定时间：2026-09-09
- 问题：工具如何真正调用被测函数。
- 选择：
  1. 直接链接调用。
  2. 编译成动态库加载。
  3. 生成桩代码交给外部框架。
  4. 纯生成、不执行。
- 用户选择：方案 1、方案 2、方案 3（三者都支持）。
- 影响：采用“序列执行器 + 适配层”架构，三种模式共享序列执行核心，由 harness 生成器统一产出驱动代码。
